# SEARCH-SCOPE — 搜索范围

不是"尽量多搜"。是**按阶段给固定的搜索半径**，超出去要么降档、要么停手。

## 四层范围

| 层 | 范围 | 用途 | 成本 |
|---|---|---|---|
| L0 | 本副本 `anchor` / `promises` / 最近 checkpoint | 每轮开头必查 | 极低 |
| L1 | 本副本历史 `trajectory/` / `mechanisms/` / `baseline/` | 兑现前查是否讲过 | 低 |
| L2 | 原初库（种子）、上游 Release（skill 与规则） | 规则更新、机制借鉴 | 中 |
| L3 | 外部（GitHub 仓库、官方文档、资料） | 知识出处、外部机制评估 | 高，且有噪音 |

## 按阶段的半径

- **BIRTH**：L0 + L3（只为确认主题存在、边界在哪）。禁止 L1——此时还什么都没长。
- **GROWTH**：L0 → L1 → L3。**每轮 L3 的调用要少**，只用来验 D1 的出处，不用来"找灵感"。
- **REGULATED**：L0 → L1 → L2 → L3。L2 在兑现前必查（规则可能已更新）。

## 硬规则

1. **先窄后宽**：能用 L1 回答的，不许开 L3。
2. **带预算**：每轮 L3 查询次数自己先定个数，写进当轮 `deliver.md` 顶部（如 `L3-budget: 3`）。超了停手，剩下的进 `gaps.md`。
3. **出去的每个结论都要带回路径**：L3 拿来的东西必须能落到"文件/链接/复核方式"，否则按 `degrade.md` 降档。
4. **不许用搜索补全结构**：搜索能给你"别人怎么教"，不能给你"这门课该怎么长"。结构永远来自本副本的 fork，不来自外部。

## 外部机制评估（允许的范围）

明确允许 Agent 去 GitHub 上看别人怎么解决"怎么抉择、怎么共享、怎么治理"。但：

- 评估的是**机制**，不是路径（CHARTER 第 1 条）
- 产出必须是 `PROP-*.md`（`kind: external-adopt`），不是直接改库
- 评的时候拿 CHARTER + 本文件当标尺，逐条比对
- 结果要**可抽检**：写清看了哪个仓库哪个文件，不是"参考了某项目"
